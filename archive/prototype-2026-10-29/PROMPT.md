# TwoPills 프로토타입 명세 (`frontend/index.html`)

Figma 파일이 없으므로 이 문서가 디자인 스펙이다. 07단계 `/figma-implement`는 이 문서의 2장과 5장에 맞춰 구현 충실도를 점검한다.
문구의 원천은 `docs/scenarios.yaml`·`docs/problem.yaml`이고, 여기서는 "어떤 요소가 어디에 있는가"와 수치를 정한다.

## 1. 전제

- 바닐라 HTML/CSS/JS 한 파일. 외부 라이브러리 없음. 폰트만 Google Fonts(Hahmlet, Gothic A1, Fraunces).
- 해시 라우팅 SPA. 로그인 상태·복용 목록은 `localStorage` 키 `twopills.v1`에 저장(try/catch).
- 조합 DB·품목 카탈로그·성분 효과는 파일 안 `DB` 객체. 출처 URL이 없는 규칙은 넣지 않는다.
- AI(사진 글자 읽기·추천 후보 고르기)는 목업: 사진은 파일 이름·샘플 버튼으로, 추천은 설문 답 → 성분 표로 흉내 낸다. 실제 구현에서 서버 호출로 바뀐다.
- 서비스 이름은 "TwoPills"(2026-10-29 사용자 지정). 로고 워드마크는 `TwoPills` 이탤릭.

### 2.2 회원가입 `#/signup`

이메일 / 비밀번호(8자 이상) / 비밀번호 확인 / 동의 체크 "복용 중인 약·영양제(건강 정보) 수집·이용에 동의해요" / 주 버튼 '가입하기' / 보조 링크 '로그인'.
오류: "이미 가입한 이메일이에요", "비밀번호는 8자 이상이에요", "비밀번호가 서로 달라요", "동의해야 가입할 수 있어요".
폼 폭 440px, 가운데.

### 2.3 로그인 `#/login`

이메일 / 비밀번호 / 주 버튼 '로그인' / '시연 계정으로 채우기' 버튼(복용자 계정을 칸에 채움) / 보조 링크 '회원가입'.
오류: "이메일 또는 비밀번호가 맞지 않아요".

### 2.4 홈 `#/home`

인사 한 줄(이메일) / 두 칸 카드 '복용 목록'(등록 수 표시), '분석하기' / 아래 '영양제 추천받기' 버튼 / 목록이 비어 있으면 "먹고 있는 약이나 영양제를 추가해 보세요" / '로그아웃'.

### 2.5 복용 목록 `#/list`

데스크톱 2열: 왼쪽 등록 패널(폭 400), 오른쪽 표.
등록 패널: 세그먼트 토글 '검색으로 등록' | '사진으로 등록'.
- 검색: 검색창 + '검색' 버튼 → 결과 최대 20개(이름·회사·쉬운 이름·종류 배지·주요 성분) → 고르면 '하루에 먹는 개수'(필수), '한 알 함량 mg'(영양제만, 선택) → '등록'.
  문구: "2글자 이상 입력해 주세요", "찾는 제품이 없어요. 성분 이름(예 칼슘)으로 검색해 보세요", "이미 내 목록에 있어요", "함량을 넣으면 하루 기준량도 확인해 드려요".
- 사진: 동의 화면("사진을 AI로 보내 글자를 읽어요. 읽은 뒤 사진은 바로 지우고 저장하지 않아요", '동의하고 찍기', '검색으로 등록') → 촬영 안내 네 줄 → 파일 올리기 + 샘플 사진 버튼 3개(흐린 알약 사진 / 훼로바-유서방정 상자 / 씬지로이드 약 봉투) → 결과: 후보 최대 5개 또는 "사진이 흐려서 읽지 못했어요. 다시 찍어 주세요" + '다시 찍기' 또는 "사진에서 찾지 못했어요. 이름으로 검색해 보세요".
표: 약 / 영양제 두 칸, 열 = 이름(쉬운 이름), 성분, 하루 복용량, '삭제'. 비어 있으면 "먹고 있는 약이나 영양제를 추가해 보세요".
삭제: "삭제할까요?" 창 → '삭제' → 토스트 "등록된 약·영양제가 목록에서 삭제되었습니다."
맨 아래 주 버튼 '분석하기'.

### 2.6 경고 창(등록 시 점검)

맨 위 단계 배지+문구("함께 먹지 마세요" / "시간을 띄워 드세요" / "하루 기준량을 넘어요") → 대처 방법(출처에 있을 때만, 예 "레보티록신과 최소 4시간 띄워 드세요") → 성분 짝("레보티록신(갑상선약) ↔ 철분") → 원문 인용 → 출처 제목+링크 → 약사에게 물을 질문 → "복용을 바꾸기 전에 약사·의사와 상담하세요" → 버튼 '자세히' '그래도 추가' '취소'.
여러 소견이면 "함께 먹지 마세요 → 시간을 띄워 드세요 → 하루 기준량을 넘어요" 순으로 전부 쌓는다.
기록이 없으면 창을 띄우지 않고 바로 등록 + 안내 카드: "확인한 자료에서는 보고된 문제가 없어요. 걱정되면 약사에게 확인하세요", 확인한 자료, 확인한 성분 짝 수, DB 확인 날짜, 약사에게 물을 질문.

### 2.7 분석하기 `#/analyze` → 보고서 `#/report`

'분석 시작' → 진행 3단계(성분 맞추기 / 조합 찾기 / 하루 합계 비교, 각 300ms) → 보고서.
보고서: 요약 3칸(주의할 항목 N / 약 N개 / 영양제 N개, Fraunces) → 소견 카드(단계·대처·성분 짝·이유·출처 링크·약사에게 물을 질문·'자세히') → 복용 중인 약·영양제 전체(이름·하루 복용량, 약사에게 보여 줄 한 줄 "레보티록신 1정, 칼슘 1000mg") → 출처 목록 → 면책 박스 → '영양제 추천받기'.
소견이 없으면 "확인한 자료에서는 보고된 문제가 없어요. 걱정되면 약사에게 확인하세요".

### 2.8 근거 상세 `#/detail/<ruleId>`

두 성분, 단계, 이유, 원문 문장, 해야 할 행동, 출처 목록(제목·종류 공식 자료/논문·연구 조건·'출처 보기' 새 창), DB 확인 날짜, '돌아가기'.

### 2.9 영양제 추천 `#/recommend` → `#/recommend/result`

면책 맨 위·맨 아래 "이 추천은 진단이나 처방이 아니에요. 새로 드시기 전에 약사·의사와 상담하세요".
설문: '원하는 효과'(여러 개: 피로 회복 / 뼈 건강 / 눈 건강 / 수면 / 면역), '지금 증상'(쉽게 피곤해요 / 잠을 잘 못 자요 / 눈이 뻑뻑해요 / 감기에 자주 걸려요 / 뼈·관절이 걱정돼요 + 짧은 글) → '추천 보기'.
결과: '추천' 칸(성분·추천 이유·효과 문장·출처 링크) / '주의' 칸("지금 드시는 ○○과 함께 주의가 필요해요" + 출처). 제품명·구매 링크 없음.
