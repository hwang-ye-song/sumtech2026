(요약은 10단계가 끝나면 맨 위에 쓴다.)

## 00. 새로 만들기 (2026-10-29)

전제 조건이던 `DESIGN.md`·`prototype/index.html`·`prototype/PROMPT.md`가 저장소에 없어서 먼저 만들었다. 폴더는 `prototype/` 대신 `frontend/` 하나에 모았다.
10개 스킬(`/frontend-design` `/impeccable` `/taste-skill` `/animate` `/design-motion` `/theme-factory` `/figma-implement` `/playwright-mcp` `/brandkit` `/designer-skills`)은 모두 설치돼 있지 않다. 각 단계는 "스킬 없음"으로 적고 같은 의도로 직접 수행한다.

### 만든 것

- `DESIGN.md` — 색·라운드·간격·타이포·컴포넌트·반응형·모션 토큰 초안. 코발트 `#1a3fe0` 하나만 채도색. 주의/과다/기록 없음 상태 색은 저채도.
- `PROMPT.md` — 화면 명세(2장)와 알약 일러스트 명세(5장). 07단계가 이 수치로 충실도를 점검한다.
- `index.html` — 바닐라 한 파일. 해시 라우팅, `localStorage`(`hanjari.v1`) 저장, 시드 계정(`user@hanjari.app` / `hanjari1234`, 레보티록신 1정 + 칼슘 1000mg).
  - 화면: 랜딩 / 회원가입 / 로그인 / 홈 / 복용 목록(검색·사진) / 경고 창 / 분석하기 / 리포트 / 근거 상세 / 영양제 추천(설문·결과)
  - 판정은 파일 안 `RULES`·`LIMITS`로만 한다(랜덤·AI 없음). 규칙 5개: 비맥스제트정↔칼슘(R7), 레보티록신↔칼슘(R3·R12), 레보티록신↔철분(R12), 칼슘↔철분(R10), 칼슘 하루 기준량(R13).
  - AI 목업: 사진은 파일 이름(`blur`/`fero`/`synth`)과 샘플 버튼 3개로, 추천은 설문 → `EFFECTS` 표로 흉내 낸다.
  - 고정 문구는 `T` 객체 하나에 모아 두었다. `docs/problem.yaml`·`scenarios.yaml` 원문 그대로.

### 바꾸지 않은 것과 이유

- 서비스 이름 "한자리"는 프롬프트 문서에 적힌 가안을 그대로 썼다. 학생 확인 필요.
- 프롬프트 공통 규칙의 인용 두 개가 docs 원문과 다르다. docs를 따랐다(e2e가 docs 문구를 본다).
  - 프롬프트 "등록된 약,영양제가 목록에서 삭제되었습니다." → docs "등록된 약·영양제가 목록에서 삭제되었습니다."
  - 프롬프트 "확인한 자료에서는 보고된 문제가 없어요. 약사에게 확인하세요" → docs "확인한 자료에서는 보고된 문제가 없어요. 걱정되면 약사에게 확인하세요"
- 회원가입에 "건강 정보 수집·이용 동의" 체크를 필수로 넣었다(F1). `scenarios.yaml` S1·S8 steps에는 동의 단계가 없으므로 08단계에서 "동의 칸에 체크한다" 한 줄을 S1·S8에 넣을지 학생 확인 필요. 그 전까지 e2e는 이 체크를 추가 step으로 다룬다.
- 성분 짝 표기: 경고 창은 "레보티록신(갑상선약) ↔ 철분"(S4·S7), 리포트·상세 제목도 같은 함수를 쓴다. S5의 "'레보티록신 ↔ 칼슘' 항목"은 제목에 쉬운 이름이 붙은 "레보티록신(갑상선약) ↔ 칼슘"으로 보인다. e2e는 부분 일치로 잡는다.
- 추천용 성분 효과 출처(MedlinePlus 백과 `002403` 등 5개)는 팀이 열어 확인한 뒤 확정해야 한다. 현재는 `SRC`에 "팀 확인 필요"로 둔 목업이다.
- 플랫폼: docs는 mobile이지만 프롬프트가 데스크톱 1200px 기준을 지정해 그대로 따르고, 760px 아래에서 1열·아래 탭으로 바뀌게 했다.

### 확인 결과

- Chrome 확장이 연결되지 않아 Playwright(라이브러리, `e2e/run.mjs`)로 확인했다. `package.json`에 `playwright`·`serve`를 devDependency로 두고 `npm run serve` / `npm run e2e`.
- S1~S8 전부 PASS, 콘솔 오류 0, 가로 스크롤 0 (1280×800). `SHOT=1`로 1280·390 × 라이트·다크(아직 라이트와 동일) 스크린샷 12장을 `screenshots/`에 저장.
- 돌리면서 고친 것: 성분 짝 표기를 규칙에 적힌 순서(약 ↔ 영양제)로 고정(S2 "비맥스제트정 ↔ 칼슘"·S4 "칼슘 ↔ 철분"·"레보티록신(갑상선약) ↔ 철분"이 한 함수로 다 맞음). 히어로 통계 4칸이 왼쪽 반에 끼던 그리드 버그.
- S3의 "'안전'이 보이지 않는다" 검사에 기관 이름 "식품**안전**나라"·"의약품**안전**나라"가 걸렸다. 화면에서는 "식약처 건강기능식품 섭취 주의사항 고시", "식약처 공식 사이트"로 바꿔 부분 일치를 피했고, 랜딩 통계의 "안전하다고 여겨"도 "괜찮다고 여겨"로 바꿨다. 실제 구현 e2e도 같은 함정이 있으니 출처 제목에 '안전'이 들어가는 자료는 표시 이름을 따로 두는 게 좋다.

### 이름 변경·3D 알약 배경 (2026-10-29, 사용자 요청 두 번)

- 서비스 이름 "한자리/hanjari" → **TwoPills**. 로고·`<title>`·aria-label과 내부 키(`twopills.v1`)·시드 계정(`user@twopills.app` / `twopills1234`)도 바꿨다. "약과 영양제를 한자리에" 같은 문장 속 표현은 이름이 아니라 카피라 그대로 뒀다. 이름은 확정이라 "학생 확인 필요"에서 뺀다.
- 배경: 흰색 → 보라 그라데이션. 가장자리는 사진 배경색(`--lav-edge #b3a6e0`), 가운데로 갈수록 `--lav-mid`·`--lav-light`로 밝아지는 가로 그라데이션(`background-attachment: fixed`). 카드는 흰색 그대로 위에 얹는다. 내비는 반투명 흰색 + 블러.
- 사진 `assets/pills2.jpg`(보라 3D 알약, 54KB)는 두 군데에 쓴다.
  1. 히어로 오른쪽: 카드 없이 가장자리를 radial 마스크로 흐려 배경에 녹인다. 스크롤하면 위아래로 움직이고 살짝 커진다.
  2. 화면 양 옆 `#pillfield`(고정 레이어): 사진에서 알약 10개를 잘라(`FIELD` 배열의 `c=[x,y,w,h]`) 각각 가장자리를 흐리고, 알약마다 다른 속도·회전으로 스크롤에 반응한다. 크고 가까운 알약은 빠르게, 작고 먼 알약은 느리게 흐르고, 화면 밖으로 나가면 반대편에서 다시 들어온다. 스크롤을 올리면 거꾸로 간다.
- 이전 사진(분홍 알약)과 "알약 무대" 구간은 지웠다.
- 2026-10-30 수정: 알약은 **양 옆 여백(콘텐츠 폭 1120px 바깥)에만** 나온다. 가운데 글 영역에는 알약이 없고 배경도 밝은 라벤더로 비워 글이 잘 보인다. 히어로 오른쪽 사진은 가운데 영역이라 빼고, 같은 자리를 "목록에 더하는 순간 이렇게 알려 줘요" 흰 카드(경고 예시 칩 3개)로 바꿨다. 콘텐츠 최대 폭을 1200 → 1120px로 줄여 1280px 화면에서도 옆 여백이 80px 남는다. 옆 여백이 56px보다 좁으면(휴대폰·작은 창) 알약을 숨긴다. 이 변경으로 "모바일은 알약을 절반 크기로 줄였다"는 위 문장은 "모바일은 숨긴다"로 바뀌었다.
- `prefers-reduced-motion`이면 알약이 스크롤에 반응하지 않고 제자리에 있다. 모바일(760px 미만)은 알약을 절반 크기·반투명으로 줄였다.
- 알려진 한계: 알약이 글자 뒤로 지나갈 수 있다(헤드라인 일부와 겹치는 순간이 있음). 알약별 투명 PNG가 있으면 흐린 가장자리 없이 더 깔끔하게 만들 수 있다. 02단계에서 글자와 겹칠 때 알약을 더 흐리게 할지 정한다.
- DESIGN.md의 "보라·그라데이션 금지, 채도색은 코발트 하나" 규칙은 이번 요청과 충돌한다. 사용자가 직접 정한 방향이라 01단계에서 규칙을 "배경은 보라 그라데이션, UI 버튼·링크는 코발트 하나"로 고친다.

### 테마색·글꼴 변경 (2026-10-30, 사용자 요청)

- 메인 색 코발트 `#1a3fe0` → **자두색(aubergine) `#5b2457`**(`--brand`, 글자용 `--brand-ink #431a40`, 옅은 면 `--brand-bg #f1e6ef`). 파랑·초록 계열을 피하고, 연보라 배경·분홍 보라 알약과 한 계열이면서 흰 글씨 대비가 충분하다. 토큰 이름도 `--cobalt` → `--brand`로 바꿨다.
- 글꼴 전부 KofihJongwook(300/700). 굵기가 두 단계뿐이라 CSS의 `font-weight:500`을 모두 700으로 바꿨다(500은 300으로 렌더링됨). 헤드라인은 가는 300 + 굵은 700 강조가 다시 살아났다. 연보라 위에서 얇은 글씨가 흐려 보여 `--ink-2`·`--ink-3`을 더 진하게 했고, 한글 제목이 어색하게 줄바꿈되지 않도록 `word-break: keep-all`을 넣었다.
- 주의(`--warn` 갈색 빨강)와 자두색이 가까운 계열이라 02단계에서 둘이 헷갈리지 않는지 확인한다.

### 랜딩(홈) 재구성 (2026-10-30, 사용자 요청)

- 통계 4칸(13/36·70.3%·15.3%·72%)과 관련 CSS를 지웠다. 랜딩에 숫자 카드가 없고, 남은 숫자는 근거 인용 안의 "최소 4시간"·"약 20~25%"뿐이다.
- 새 순서: 히어로(실제 경고 화면 미리보기 카드) → 왜 필요한가요(따로 들어옴·아무도 안 물음·물어도 찜찜함) → 다른 점 비교표(유튜브·SNS / 생성형 AI / TwoPills) → 누구에게(20~30대·자녀·부모님) → 사용 방법 4단계 → 근거 인용 3개 → 약속 4개 → 가입 CTA. 내용은 모두 `problem.yaml`의 대안·페르소나·경험에서 가져왔고 수치를 새로 만들지 않았다.
- S1 expected의 "처방이나 진단을 하지 않아요" 안내와 '회원가입' 버튼, F2의 4단계 사용 방법은 그대로다.
- 확인 필요: "AI는 판정하지 않아요"·"다른 팀원이 대조한 것만 넣어요"는 problem.yaml F7 절차를 그대로 약속으로 쓴 것이라, 실제 데이터를 넣을 때 지켜야 한다.

### 상단 내비게이션·약·영양제 알아보기 (2026-10-30, 사용자 요청)

- 내비게이션 항목: **약·영양제 알아보기 / 복용 목록 / 분석하기 / 영양제 추천**(로그인하면 맨 앞에 '홈'). 로그인 전에도 모두 보인다.
- 새 화면 `#/explore` "약·영양제 알아보기"는 **로그인 없이** 쓴다. 카탈로그 14개를 검색(제품명·성분·흔히 부르는 이름)하고 약/영양제로 거를 수 있으며, 항목마다 DB에 기록된 함께 먹을 때 주의(단계 배지, 대처, 이유, 출처 링크)와 하루 기준량을 보여 준다. 기록이 없으면 "확인한 자료에서는 보고된 문제가 없어요. 걱정되면 약사에게 확인하세요"만 쓰고 '안전'이라는 말은 쓰지 않는다. '내 목록에 더하기'로 복용 목록에 이어진다.
- 로그인이 필요한 메뉴(복용 목록·분석하기·영양제 추천)를 로그인 전에 누르면 로그인 화면으로 가고, 로그인(가입)하면 **누르려던 화면으로 돌아간다**. 직접 로그인 화면으로 들어가면 예전처럼 홈으로 간다.
- 모바일(760px 이하): 로그인 전 내비에는 '알아보기'만 남기고, 아주 작은 폰(359px 이하)은 숨긴다. 로그인 후 아래 탭은 홈·알아보기·복용 목록·분석하기 4개다. 영양제 추천은 홈 버튼과 리포트 맨 아래 버튼으로 들어간다.
- 주의: '알아보기'는 e2e S1~S8 흐름에 없는 새 화면이라 e2e를 추가하지 않았다. 03단계에서 `scenarios.yaml`에 흐름으로 넣을지 팀과 정한다. 사전 기능은 problem.yaml features(F1~F9)에 없는 추가 화면이므로, 팀이 범위로 인정하는지 확인이 필요하다.

### 다음 단계로 넘기는 메모

- 01: 히어로 떠다니는 패널과 "가는 300 + 굵은 700 코발트" 헤드라인은 들어가 있다. 가운데 정렬 남발은 없지만 STEP 카드·스펙 그리드의 radius가 모두 22라 균일하다. 섹션 사이 리듬을 점검할 것.
